Proof that the build happened the way the write-up says. Every file here is
either a raw export or is regenerated by a committed script; nothing is
hand-written except this README.

| File | What it proves | How to regenerate |
|---|---|---|
| `cloudtrail-timeline.md` | Every AWS management API call made under the build IAM user (`arn:aws:iam::232351199908:user/MohitkPatwari@2005`) in ap-south-1 and us-east-1: a count per service, a count per caller (aws-cli, sam-cli, console, or AWS acting on our behalf), and a full UTC timeline with error codes. ## Limits, stated plainly

- CloudTrail Event history holds **management events only**. Data events
  (Lambda Invoke, S3 object reads) are not in it and are not claimed.
- The coding agent and the human share one IAM user, so CloudTrail cannot tell
  them apart by principal. The *Caller* column uses `userAgent`: terminal calls
  (`aws-cli`, `sam-cli`, `Boto3`) came from the Claude Code sessions or the human
  typing in the same terminal; `console` rows are the human in a browser.
- Event history lags real time by up to ~15 minutes, and the export is a
  snapshot. Rerun the script at the end of the build.
- Calls made by the deployed Lambdas' own execution roles (e.g. `/health`
  reading SSM) are excluded by the principal filter.

The dataset audit is not here: `analysis/audit_lecture_halls.py` reproduces it,
